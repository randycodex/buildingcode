# Long conversations — local evaluation, November 16, 2026

The reported chat had 20 messages and 154 unique section/edition sources. A read-only reconstruction of the failing request was 181,256 bytes, exceeding an application guard at 180,000 bytes before provider dispatch. The accumulated source catalog accounted for about 106 KB. This was an app limit, not a refusal to answer or exhaustion of the test budget.

The Experimental Assistant no longer applies that fixed request-byte ceiling. Its model, tool and spending checks remain distinct from chat length. Full messages and immutable source records stay in storage. Each answer receives an automatically selected working context, prioritizing the current exchange and the explicit current question, with relevant older facts/corrections and source discovery cards. Source deduplication preserves distinct excerpt, table and visual-content identities. No stored record is deleted or rewritten to make the model request smaller.

The complete active archive is searchable through local conversation tools. Search results have continuation offsets; complete message pages and source IDs can be reopened. Reopened code evidence passes the existing edition/content checks and receives current citation IDs. Historical web-source identities remain discoverable but are labeled as historical references, not freshly verified authority. A source card is not a citation. All archive access stays within the current account/conversation/context revision.

If the provider actually rejects context or payload size, the Assistant retries automatically with a smaller working request, retaining that compact mode through the rest of the answer. Deferred evidence remains readable. A repeated failure has a dedicated, clear message saying that the complete conversation and sources are saved and a new chat is unnecessary. Local configuration and test-budget failures have separate messages. The old reviewed-engine policy is preserved as a rollback option.

Validation:

- Offline stress: 2,000 messages and 2,000 sources, remote corrections, superseded assumptions, explicit returns to older topics, source recall, message/search pagination, source hashes and archive immutability. Explicit questions outrank repetitive recent-topic vocabulary. Historical web identities remain distinct from verified contents.
- Full HTTP integration: more than 1,000 saved messages, a distant width correction, an earlier actual library source reloaded/cited, unchanged hashes for the original messages and immutable answer records, and no deletion after a simulated provider-capacity failure. Automatic retry and the dedicated saved-history error passed. These provider responses were offline doubles, with no paid calls.
- Real Luna: 2,000 pre-existing messages and 2,000 fictional project-document sources. Three natural follow-ups correctly recalled a confirmed 42-inch dimension over an unverified 39-inch assumption, returned to a 60-inch courtyard decision replacing a 48-inch draft, and reopened/cited the exact saved project note. The source archive hash was unchanged. These were project-memory tests, not statements of NYC legal minima. Answers took 8.8, 5.1 and 6.3 seconds. Model requests were about 11–49 KB.
- Read-only reconstruction of the user's reported chat: all 20 messages and 154 section/edition sources remained saved. The selected working context was about 34 KB, including 26 relevant source cards, before the separate library guide/prompt overhead. No real-user question was sent to the provider for this inspection.
- Existing experimental flow, navigation/direct reads, table/footnote integrity, reviewed-engine runtime and provider cost/budget checks passed. An existing test that assumed all unrelated source cards are always forwarded was updated to assert that the full archive remains available while the working window omits irrelevant cards.

There is no message-count or stored-source-count cutoff introduced by this change. A working model request is finite; the archive tools allow retrieval beyond it rather than pretending all historical text is present simultaneously. The tests demonstrate the tested recall cases and preservation, not perfect semantic recall for every possible question. Code-research latency was not benchmarked by the project-memory test.
