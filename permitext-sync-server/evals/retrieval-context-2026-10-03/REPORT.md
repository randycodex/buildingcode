# Retrieval context candidate — source-reviewed checkpoint

The frozen candidate is **not accepted for production**. The 36-turn reserved run delivered 27 correct answers, 1 appropriate clarification, 7 unnecessary nonanswers, and 1 materially wrong answer. Twenty-eight turns passed the stated rubric (77.8%); 7 of 12 three-turn conversations passed completely. This is a diagnostic result from assistant-authored, correlated scenarios and assistant source review, not representative product accuracy or professional adjudication.

## What the candidate changed

- Search receives bounded, relevant structured project facts while retaining their scope, qualification and negation. Current corrections and hypothetical scenarios supersede inherited use, district and edition hints. Existing-property inventory is not treated as the proposed replacement building.
- Generic source titles no longer erase the prior user subject on related follow-ups. An explicit new code family or edition removes stale inherited reference hints.
- Canonical zoning chapter/use metadata provides a soft ranking prior. Alternatives remain discoverable; an exact current reference wins. Search metadata does not determine legal applicability.
- Eligible construction-code evidence receives bounded, edition-matched interpretation context. It follows the operative rules and dependencies, precedes optional definitions, and cannot override strict selected-text restrictions or consume space reserved for primary evidence.

Focused contracts cover these changes, canonical identity, complete dependencies, exact pins, bounded evidence, cross-family/edition resets, and project-linked HTTP follow-ups. They establish local behavior, not hosted acceptance.

The seven nonanswers have separate causes:

- One fuel-gas follow-up missed the available impact-protection provision and therefore left the question unresolved.
- A fire-code rooftop answer was blocked by a zoning conclusion guard before subjective verification.

The materially wrong rooftop-door answer asserted that no fixed clearance was specified after retrieval omitted the applicable child subsection. Absence from the selected evidence must not be presented as absence from the law.

Some corrected custom numeric facts remained stale semantic-query hints. Those particular delivered answers applied the current corrections correctly, so this is recorded as a non-failing observation rather than a retroactive grading failure.

## Evaluation integrity and cost

Fixtures, source packets and keys were frozen before paid answers; the candidate was frozen before opening or running reserved questions. All 137 recorded source-file hashes and 7 fixture-file hashes matched at final review. Twelve isolated fictional projects were used; each conversation's three turns retained its own project link. This checks the exercised local HTTP path, not every production UI entry path.

The separate 10-turn development run had 8 correct answers and 2 minor issues, with all 10 narrow operative conclusions correct. It is excluded from the reserved score. A tracking-only runner hash-list edit made after development started is explicitly recorded in the candidate freeze note; application modules remained unchanged.

One dryer question's frozen key overstated an absolute named-material prohibition. The truthful conditional answer and focused product-specification clarification passed the rubric; the caveat is preserved in Part B without rewriting the frozen key. No score is based solely on HTTP status or verifier approval.

All 164 calls in these two runs are settled. Their configured token-rate cost estimates were $0.06146247 for development and $0.195195255 for the reserved run. The shared campaign ledger records 1,628 settled calls and approximately $1.61632 against the $13.97 cap, with no outstanding reservations. This is ledger accounting, not verification of the provider invoice or account balance.

The reserved run's full-turn warm local timing was p50 12.46 seconds and p90 35.39 seconds. Fixture preflight warms corpus and query caches; this does not establish hosted or cold-start performance. Generation used the existing Luna low writer and medium verifier; no production model configuration, normal user history, push or deployment changed.
