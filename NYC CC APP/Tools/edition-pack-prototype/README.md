# Local edition-pack installation prototype

Host Swift package; no app integration, network downloader, device or simulator. Run `swift test`, or `swift run edition-pack install SOURCE ROOT TRUSTED_MANIFEST_SHA256`.

SOURCE contains `manifest.json` and exactly its listed regular files. Manifest schema 2 requires `readerCompatibility` (the host prototype defaults to `prototype-v1`) and has explicit `packID`, `revision`, `bundlePath`, structured `sourceIdentities`, and `files` entries (`path`, `bytes`, lowercase `sha256`). The supplied digest must come from an independently trusted release channel. This prototype does not establish that trust, sign manifests, or establish remote catalog trust. Canonical identities match the app fields (`canonicalEdition`, `jurisdictionID`, `codeID`, `categoryID`); after file hashes pass, validation requires exact identity coverage of the included `bundle.json` metadata. Old schema1 prototype exports must be regenerated; no app migration is implied.

Installation validates, copies into private staging, validates again, moves to an immutable revision directory and atomically replaces a small active pointer. Previous revisions remain available for explicit validated rollback. Failure before activation preserves the prior pointer. Reinstalling an existing revision requires the exact same manifest. Source and store must not be concurrently mutated: this is single-writer local-directory transport, not a hardened adversarial downloader. Use canonical macOS temporary paths (`/private/var/...` rather than the `/var` symlink).

Storage-budget and interruption closures support deterministic tests. The default budget is unlimited (`Int64.max`), so production integration must supply actual available-space checks plus filesystem overhead/headroom. Logical budget includes payload and manifest bytes, not APFS metadata or temporary overhead. Atomic pointer replacement is not a power-loss durability/fsync guarantee. No automatic garbage collection, persistent download resume, archive extraction, multiwriter locking, signature distribution, native catalog integration, or active Reader reference counting is provided.

`PackStore(root:supportedReaderCompatibility:)` rejects a missing identifier during decoding and an unsupported identifier before copying or activation, including rollback. The identifier is an explicit prototype reader contract, not an iOS version compatibility claim. Previously exported manifests without this field are pre-gate artifacts and must be regenerated; their performance receipts do not establish compatibility-gate acceptance.

`swift run edition-pack verify ROOT PACK_ID` reopens and validates the complete active manifest and every installed payload, without source/download access. This is a host verification tool, not a recommended full-hash scan on every app launch. `verifiedActiveManifest` provides this validation; `activeRevision` remains pointer introspection only.

Export using `python3 Tools/performance/prepare_edition_pack.py SOURCE DESTINATION` from the repository root. Bundled sources derive their canonical path from the resource root; external synthetic fixtures must supply `--bundle-path CodeContent/authored/JURISDICTION/PACK/bundle.json`. The canonical path must match the source directory name and is included in revision identity.
