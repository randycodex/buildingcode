# Multi-tab update acceptance — September28

## Fix

New service workers no longer force activation or claim existing documents. Controlled older tabs retain their worker/cache until all of those tabs close. Natural activation then deletes superseded shell caches. There is no forced page reload and no unbounded retained-generation policy.

Manual offline preparation recognizes an installed waiting update. It returns without refetching/replacing the old manifest only when the calling document is controlled and its own shell cache contains matching workspace HTML and all55 required entries. Missing/invalid assets or an uncontrolled document produce a clear close-and-reopen instruction. First installation still waits for activation; the initial uncontrolled document is not claimed and becomes controlled on navigation.

Production version: v606 (`20260928-waiting-update-v606`), shell1249. Existing loaded v605 JavaScript is not retroactively fixed. It may still wait for activation during manual preparation; closing all old tabs permits the new code to take effect. New releases take effect after old controlled tabs close, not merely after a single tab reload.

## Browser evidence

An isolated localhost fixture served production module bytes and exact Notebook JS/CSS URLs with no-store HTTP headers, avoiding HTTP-cache masking. Future v607/shell1250 was generated by changing version identifiers only; it is not a published release.

1. First install completed with55 entries and controller=null. Intentional navigation/reload established control.
2. Two baseline controlled diagnostic tabs opened. TabA loaded the actual Notebook module and stylesheet; old cache grew to57 entries. TabB had never imported them.
3. Update installed and waited. Both caches existed; only the old cache contained Notebook assets. Manual preparation from the old document succeeded without forcing activation.
4. Fixture GET transport was disabled. TabB’s first Notebook import and stylesheet load succeeded with expected exports and no errors; worker remained waiting. No component was mounted and no private data was touched.
5. Transport restored. Closing TabA left the update waiting while TabB remained. Closing TabB allowed natural activation. A newly opened tab used the new generation; only shell1250 remained with55 entries.

Visible diagnostics: `PERF_MULTITAB_ROLLOUT_2026-09-28.json`; screenshot: `PERF_MULTITAB_ROLLOUT_2026-09-28.png`. Diagnostic UI and fixture server were closed after verification.

## Tests and limits

Full `npm run smoke` and `npm run test:shell-rollout` passed. Actual-function cases cover lifecycle callbacks, first-install activation, installing-to-waiting transition, already-waiting readiness, every missing manifest entry, mismatched HTML, uncontrolled rejection, and no waiting-path asset writes/fetches. Existing failed-update/retry/stream-body tests remain passing.

This is real browser worker/lazy-public-asset acceptance, not full private Notebook/Report offline acceptance, Safari/iOS PWA acceptance, or hosted/Production verification. The fixture does not exercise a changed definition-registry version independently. No claim is made that never-downloaded lazy modules become available offline. Hosted v606 identity now passes; see `PERF_PREVIEW_WAITING_UPDATE_2026-09-28.json`.
