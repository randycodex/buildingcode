# Resume references after Reader interruption

Source735968cd2 corrects a retained Reader lifecycle gap. Previously a passage body could publish, then the Reader disappear while reference resolution was suspended. Disappearance invalidated the completion generation, but the next appearance skipped all loading because the body already existed. The references could remain absent indefinitely.

Reader now tracks unfinished reference work separately from the body, remembers its loaded edition, and resumes only that work on reappearance. Completed results, including empty reference lists, do not resolve again. Account request identity, edition and cancellation guards reject stale completion. Bookmark/note UI state synchronizes as soon as the body publishes, without waiting for references.

`python3 Tools/test_reader_reference_resume.py` executes the extracted production reference state, async resume method and task decision with a deferred resolver. It verifies disappearance/reappearance, rejected old completion, successful new completion, no body reload, completed-empty reuse and account-change rejection.
