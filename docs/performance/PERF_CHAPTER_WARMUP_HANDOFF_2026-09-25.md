# Chapter warmup handoff follow-up

Scope: reduce work competing with explicit chapter navigation while retaining current/recent priority. Physical baseline41.24 is recorded separately; no before/after speed claim yet.

1. Startup/re-entry priority selection previously rebuilt a dictionary for every section in all candidate chapters on the main actor. It now uses the existing store section index, accepts only candidate chapters, and stops when the four-chapter shortlist is full. Empty history performs no section lookups. Last-opened priority, recent order, edition/category boundaries and fallback ordering remain intact.
2. Explicit chapter opening previously waited for preparation to finish before cancelling unrelated warmups. Native preparation now offers an acquisition callback after atomic demand registration (or a memory-cache hit). The caller suspends speculative work then, so the selected shared decode keeps its demand consumer while unrelated consumers cancel. Deferred cleanup still covers fallback and cancellation before acquisition. Cancellation of synchronous work remains cooperative; this does not promise instantaneous interruption of an ongoing decode.

Four executable suites pass: chapter warmup priority, resume, opening fast path, and native prepared cache admission. The latter two compile extracted production methods under Swift6 strict concurrency and prove selected ownership survives while unrelated work cancels, including acquisition-time cancellation.
